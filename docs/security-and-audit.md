# 数据合规、安全与审计说明

## 1. 数据分类与用途

| 数据 | 存储 | 风险与处理 |
|---|---|---|
| 用户账号、角色、密码哈希 | PostgreSQL | 密码仅保存 BCrypt 哈希；演示账号不得复用于真实系统 |
| 农场、地块、种植档案 | PostgreSQL/PostGIS | 课程演示数据，不录入精确个人住址或个人敏感信息 |
| 病害图片 | MinIO | 仅保存作物病害图片；通过 Backend 鉴权读取，不公开 bucket URL |
| AI 诊断、Agent 输入输出 | PostgreSQL | 作为辅助建议，保留人工审核状态和引用来源 |
| 知识文档、模型文件 | PostgreSQL + AI 服务文件/卷 | 记录版本、来源、路径和部署状态，便于追溯 |

模型验证数据规模较小，只用于课程学习；系统不宣称可替代专业农技人员或用于生产级自动决策。

## 2. 身份认证与权限

- Spring Security 使用无状态 JWT；登录和注册外的业务接口默认要求认证。
- 密码通过 BCrypt 编码；JWT Secret、数据库密码、MinIO 密钥和外部 API Key 从环境变量读取。
- 角色包含 Farmer、Technician、Coop Manager、Admin，并通过 URL 规则与 `@PreAuthorize` 限制操作。
- Service 层校验农场、种植周期、诊断图片和任务的实际所有权，避免仅靠前端隐藏按钮。

## 3. 输入、文件与接口安全

- Bean Validation 校验必填字段和基本格式。
- 图片上传校验：非空、MIME 白名单、扩展名白名单、20MB 限制、SHA-256 重复检测、种植周期归属。
- MinIO 对象名由服务端生成 UUID 前缀，降低重名覆盖风险；对象只通过鉴权接口读取。
- 统一异常结构返回业务错误码；内部异常堆栈只写服务日志。
- Nginx 统一代理入口，PostgreSQL、Redis、MinIO 和 AI 内部地址不暴露给浏览器。

## 4. AI 风险控制

- 低置信度和未知病害进入人工审核，不直接生成最终生产决策。
- 建议附带 RAG 文档标题和片段，便于农技人员核对依据。
- Agent 明确展示天气、生育期、知识与防治四步轨迹，避免黑盒展示。
- 未配置外部 LLM Key 时使用确定性模板，不将课程数据发送到未知第三方。
- 管理员可查看模型 Runtime、类别数、文件路径和评测指标；知识文档支持发布、同步和归档。

## 5. 审计机制

`@AuditLog` + AOP 记录关键写操作的：

```text
operator | action | controller method | elapsed time | SUCCESS/FAILED
```

覆盖用户、农场、地块、种植周期、图片上传、审核、反馈、任务、天气、知识和模型等关键操作。Agent 运行另写入 `agent_runs`，保存诊断关联、状态、摘要与耗时。

当前审计日志写入容器标准日志，适合课程演示；生产环境应接入集中日志、持久保留、访问控制和脱敏策略。

## 6. 安全验收清单

- [x] 错误密码不能登录。
- [x] 未登录请求被拒绝。
- [x] 农户不能读取他人诊断与图片。
- [x] 农户不能执行农技审核。
- [x] 非图片上传被 Backend 拒绝。
- [x] 重复图片哈希被拒绝。
- [x] 密钥不硬编码在业务代码中。
- [x] 关键写操作产生审计日志。
- [x] AI 结果需要人工审核并保留引用。

## 7. 已知边界

1. 这是课程演示系统，未完成等保、渗透测试、WAF、密钥轮换和灾备演练。
2. 审计日志当前未写入独立不可篡改审计库。
3. MIME 与扩展名校验降低误上传风险，但生产环境还应增加文件魔数、病毒扫描和图片重编码。
4. 演示账号密码公开在项目说明中，只能用于本地课程环境。
