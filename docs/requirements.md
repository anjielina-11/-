# 需求规格说明

## 1. 项目目标

建设面向云南特色农业的智能诊断与生产管理平台，将农场地块、种植档案、病害图片、AI 识别、农技审核、防治任务和效果反馈连接为可演示的业务闭环。

## 2. 用户角色

| 角色 | 主要职责 |
|---|---|
| 农户（Farmer） | 管理自己的农场、地块和种植周期；上传病害图片；查看诊断；执行任务并反馈效果 |
| 农技人员（Technician） | 查看待审核诊断、检查图片与 AI 建议、完成人工审核、维护知识内容 |
| 合作社管理人员（Coop Manager） | 查看生产概览、天气趋势、市场行情和区域统计 |
| 系统管理员（Admin） | 管理用户、角色、模型版本、知识文档和系统状态 |

## 3. 核心业务闭环

```text
农场/地块 → 作物/种植周期 → 图片上报 → AI 分类 → RAG 检索
→ Agent 防治建议 → 农技审核 → 自动生成任务 → 农户执行 → 效果反馈
```

## 4. 功能需求

| 模块 | 必需能力 | 当前实现 |
|---|---|---|
| 登录与权限 | 登录、Token 鉴权、角色路由、资源归属校验 | 已实现 |
| 农场与地块 | 新建农场、地块 CRUD、只访问授权资源 | 已实现 |
| 种植档案 | 作物与种植周期创建、修改、删除和查询 | 已实现 |
| 病害上报 | 点击/拖拽上传、图片存储、重复检测、异步诊断 | 已实现 |
| AI 诊断 | 18 类分类、未知样本拒识、置信度、严重程度 | 已实现 |
| RAG 与建议 | 从农业知识文档检索引用并生成可审核建议 | 已实现 |
| 人工审核 | 查看原图、诊断详情、批准或驳回 | 已实现 |
| 农事任务 | 审核通过自动建任务、任务状态流转、反馈 | 已实现 |
| 天气与市场 | 未来七天天气、手动更新、市场趋势 | 已实现 |
| 管理与监控 | 用户、模型、知识库和基础指标管理 | 已实现课程演示范围 |
| 一键部署 | Docker Compose 启动 Frontend、Backend、AI、DB、Redis、MinIO | 已实现 |

## 5. 数据要求

- 业务数据由 PostgreSQL 保存，数据库结构通过 Flyway migration 管理。
- 图片保存在 MinIO，数据库只保存对象路径和业务元数据。
- Redis 用于缓存和辅助状态管理。
- AI 模型、类别映射、Chroma 向量库和知识文档位于 `ai-service/`。
- 训练和验证数据只用于课程研究与演示，不宣称具备生产级泛化能力。

## 6. 非功能要求

### 安全

- 未登录请求必须被拒绝。
- 农户不能读取或修改其他农户的数据。
- 管理接口按角色授权。
- 密码、JWT Secret 和外部 API Key 通过环境变量配置。
- 上传文件校验类型、大小和业务归属。

### 可用性

- 空数据展示明确空状态，不出现白屏。
- 网络失败、AI 失败和无效输入有用户可理解的提示。
- 表单提交期间防止重复操作。
- AI 无外部 LLM Key 时仍提供带真实 RAG 引用的确定性建议。

### 可维护性

- Frontend、Backend、AI 服务解耦。
- 接口统一使用 `/api/v1` 版本前缀。
- 路径从服务根目录或环境变量解析，不依赖开发者电脑路径。
- 核心逻辑具备自动化测试，交付前执行完整构建和集成验证。

## 7. 验收标准

1. Docker Compose 六个服务全部 healthy。
2. 四类账号可以登录并进入对应页面。
3. 至少完整演示一次“图片上传—AI 诊断—人工审核—任务反馈”。
4. Frontend、Backend、AI 自动化测试通过。
5. Swagger、健康检查、关键页面和上传图片均可访问。
6. 提供需求、设计、接口、测试和协作材料。

详细测试结果见 [testing-and-acceptance.md](testing-and-acceptance.md)。
